EcoShare: OOP Design Patterns & Architecture

This reference document contains the full UML Class Diagram, OOP pillar breakdowns, and common viva questions prepared for your project defense.

1

Encapsulation

Implementation: In User and Item, sensitive fields (e.g., _email, _phone, _eco_score) are protected attributes.

  • Input validation inside @email.setter and @phone.setter.
  • get_masked_contact() masks personal contact details.
  • Mutation of eco-points only occurs through controlled methods (add_eco_score).
2

Inheritance

Implementation: Base class Item captures common metadata (id, title, category, owner, status).

  • DonationItem adds condition & estimated market value.
  • RentalItem adds rental fee per day, security deposit, and duration limit.
  • RecyclableWaste adds material type, weight in kg, and material grade.
3

Polymorphism

Implementation: The abstract method calculate_environmental_impact() is overridden differently in every subclass:

  • Donation: Computes avoided manufacturing CO2e.
  • Rental: Computes lifecycle extension offset.
  • Recyclable: Computes direct landfill diversion based on mass and material indices.
4

Abstraction

Implementation: Abstract base classes using Python's abc.ABC.

  • Transaction (ABC) declares abstract process_completion().
  • NotificationService (ABC) decouples message dispatch from business transactions.

GoF Design Patterns Demonstrated

🏭 Factory Method Pattern

ItemFactory.create_item() decouples client code from the specific constructors of DonationItem, RentalItem, and RecyclableWaste.

🔒 Singleton Pattern

DatabaseManager ensures a single coordinated connection pool to the SQLite persistence layer with lazy initialization.

Top Viva Questions & Answers

Q1: Why did you choose Python's abc module instead of standard inheritance?

Ans: The abc (Abstract Base Class) module prevents incomplete instantiation. If any subclass fails to implement calculate_environmental_impact(), Python raises a runtime TypeError, enforcing strict interface compliance.

Q2: How does this project map to UN Sustainable Development Goals (SDGs)?

Ans: It directly targets SDG 11 (Target 11.6: Municipal solid waste management) and SDG 12 (Target 12.5: Substantially reduce waste generation through prevention, reduction, recycling and reuse).

Q3: How does the system handle loose coupling?

Ans: Through Dependency Injection and Abstraction: the NotificationService interface can be swapped from in-memory logging to SMTP Email or SMS dispatch without altering transaction handling code.
